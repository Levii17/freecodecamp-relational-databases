## 1. Code Editors vs IDEs

### Code Editor vs IDE

#### What it is
- **Code editor:** Any application that lets you edit code files. It focuses on the **text** of the file.
- **IDE (Integrated Development Environment):** A full application that lets you **compile, run, and debug** your code while you edit it.

#### The Everyday Analogy
A **code editor is a notebook and pen**: fast, simple, and you can write anything in it. An **IDE is a fully equipped workshop**: it has the notebook, plus the power tools, measuring gear, and testing bench, all in one building.

#### Why it matters
- Editors are **lightweight and flexible**, great for many languages and quick edits.
- IDEs are **heavier but more powerful**, great when a project needs deep, built-in tooling.
- Knowing the difference helps you pick the right tool and not fight it.

#### Quick Example

| | **Code Editor** | **IDE** |
|---|---|---|
| **Focus** | Text contents of files | Whole development workflow |
| **Built-in tools** | Minimal (extend with plugins) | Compile, run, debug, deploy |
| **Weight** | Light and fast | Heavier |
| **Examples** | VS Code, Sublime Text, Notepad++ | Visual Studio, Xcode, Android Studio |

> **Good to know:** The line is blurry. VS Code is called an editor, but with extensions it can behave a lot like an IDE.

---

### Popular IDEs

#### What they are
Full environments, usually built for a **specific platform or ecosystem**.

#### The Everyday Analogy
**Specialist workshops.** A bicycle repair shop has exactly the tools bicycles need, but you would not rebuild a car engine there.

#### Why it matters
- Each one comes with the **debuggers, emulators, and build tools** its platform needs.
- Picking the matching IDE saves hours of setup.

#### Quick Example

| IDE | Made by | Best for |
|---|---|---|
| **Visual Studio** | Microsoft | Building, debugging, and deploying apps across many platforms |
| **Xcode** | Apple | macOS, iOS, watchOS, and tvOS apps |
| **Android Studio** | Google | Building, debugging, and testing Android apps |

---

### Popular Code Editors

#### What they are
Text-focused tools that handle many languages, with extra features added through **plugins or extensions**.

#### The Everyday Analogy
A **Swiss Army knife.** It starts simple, and you unfold exactly the tools you need.

#### Why it matters
- **Fast startup** and low resource use.
- **One tool for many languages and project types.**
- **Customizable** with themes, plugins, and settings.

#### Quick Example

| Editor | Highlights |
|---|---|
| **Visual Studio Code** | Lightweight and open-source (by Microsoft). Many languages. Debugging, syntax highlighting, and version control, with more through extensions. |
| **Sublime Text** | Fast and sleek. Customizable syntax highlighting and plugins. |
| **Notepad++** | Free and open-source, **Windows only**. Syntax highlighting, code folding, and plugins. |

---

### Cloud-Based Editors

#### What they are
Editors that run in your **web browser**, with nothing to install locally.

#### The Everyday Analogy
**Google Docs versus Microsoft Word.** You open a tab and start working, from any computer, and sharing is built in.

#### Why it matters
- **Zero setup:** useful for learning, quick demos, and borrowed computers.
- **Easy sharing and collaboration** through a link.
- **Consistent environment:** everyone on the team starts from the same setup.

#### Quick Example

| Cloud editor | What it is |
|---|---|
| **Replit** | Collaborative coding in many languages. Write, run, and share from the browser. |
| **GitHub Codespaces** | Instant, fully configured dev environment launched from a GitHub repo. |
| **StackBlitz** | Build, test, and share **web projects** directly in the browser, with no local setup. |

---

### Choosing the Right Tool

- **Highly extensible tools** (like VS Code) fit many project types and languages.
- **Specialized tools** (like Xcode) fit a narrow set of projects extremely well.
- You may use **different tools for different projects**, and that is normal.

> **Dev Tip:** Do not hunt for "the best editor". Pick one that fits your current project, learn it deeply, and switch only when it actually slows you down.

## 2. Installing VS Code

### What it is
**Visual Studio Code (VS Code)** is a free, open-source code editor by Microsoft. This section covers getting it onto your machine.

### The Everyday Analogy
Setting up a **new workbench**. First you buy the right bench for your room (your operating system), then you start organizing tools on it.

### Why it matters
- Everything else in this guide depends on a working install.
- Installing the **wrong product** is the most common beginner mistake.

> **Careful:** **Visual Studio Code** and **Visual Studio** are **different products**. Make sure you download from the **VS Code** website.

### Quick Example: Install by Operating System

**Windows**
- Download the `.exe` installer, run it, and follow the setup wizard.
```powershell
# Optional: install from the command line instead
winget install Microsoft.VisualStudioCode
```

**macOS**
- Download the `.zip` archive, which contains a `.app` you can run, **or** use Homebrew:
```bash
brew install --cask visual-studio-code
```

**Linux**
- Download a `.deb` or `.rpm` file directly.
```bash
# Debian/Ubuntu example (adjust the filename to what you downloaded)
sudo apt install ./code_*.deb
```
- Launch it from your app menu or with the CLI command, typically `code`.

> **Dev Tip:** Download installers only from the official VS Code site, because lookalike download sites exist and a tampered installer runs with your user permissions.

## 3. Creating and Running a Project in VS Code

### Workspaces and Directories

#### What it is
- A **workspace** is how VS Code thinks about a project: it is simply **whichever directory (folder) you opened** in VS Code.
- A **directory** is another name for a folder.

#### The Everyday Analogy
A **desk with a specific project's papers on it.** When you "open a workspace", you are sitting down at that desk with everything for that one project in reach.

#### Why it matters
- VS Code searches, runs tasks, and applies settings **relative to the open folder**.
- Always opening the project **folder** (not a single file) gives you the explorer, search across files, and the right context.

---

### The Command-Line Interface (CLI)

#### What it is
A **CLI** lets you control your operating system with **text commands** instead of clicking.

#### The Everyday Analogy
**Texting instructions versus pointing at things.** Typing "make a folder called my-project" is more precise, repeatable, and scriptable than right-clicking through menus.

#### Why it matters
- Nearly every developer tool uses the command line.
- Commands can be saved, shared, and automated.
- Which app you use depends on your system: **Command Prompt or PowerShell** on Windows, **Terminal** on macOS.

#### Quick Example

```bash
# Go to your home directory
cd ~                      # PowerShell or macOS/Linux Terminal
cd /d %USERPROFILE%       # Windows Command Prompt

# Make a new directory (mkdir = "make directory")
mkdir my-project
```

---

### Opening a Folder in VS Code

#### What it is
Several ways to open your project directory as a workspace.

#### Why it matters
Pick whichever is fastest for you. The CLI route is the one you will end up using most.

#### Quick Example

- **Right-click menu:** open VS Code from your file explorer (if your OS offers the option).
- **Double-click the VS Code app**, then use **File > Open Folder**.
- **Command line:**
```bash
code /path/to/folder
code .          # open the current folder
```

**macOS one-time setup:** The `code` command is **not available in Terminal until you enable it**.
1. Open VS Code.
2. Press `Cmd + Shift + P` to open the Command Palette.
3. Run **Shell Command: Install 'code' command in PATH**.

After that, `code` works from any Terminal window.

---

### Creating a File

#### Quick Example
1. Click **File > New File...** in the top-left corner.
2. Name it `index.html` and save.
3. It appears in the **Explorer** tab. Add some HTML:

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>My First Page</title>
  </head>
  <body>
    <h1>Hello, world!</h1>
  </body>
</html>
```

---

### Live Server: Run Your Page the Right Way

#### What it is
**Live Server** is a free extension that serves your HTML through a **local web server**, with automatic reload when you save.

#### The Everyday Analogy
Opening an HTML file directly is like **reading a recipe off the printer tray**. Live Server is like **putting it on a proper stand in the kitchen**, where everything behaves like it will in real life.

#### Why it matters
- Opening a file directly (`file://...`) can cause **unexpected bugs**, such as CSS or assets not loading properly.
- A proper server (`http://localhost`) behaves like a real website.
- Your browser **refreshes automatically** when you save, which speeds up your feedback loop.

#### Quick Example
1. Open the **Extensions** tab in the left sidebar.
2. Search for **Live Server** and install it.
3. Open your HTML file and click **Go Live** in the status bar.
4. Your page opens in the browser. If it does not, visit:

```text
http://localhost:5500/
```

You can also install it from the terminal:

```bash
code --install-extension ritwickdey.LiveServer
```

> **Dev Tip:** If a page works through Live Server but breaks when you double-click the file, the cause is usually a path, module, or request that needs a real server, so always test with a server running.

## 4. Keyboard Shortcuts

### What it is
Key combinations that perform actions without reaching for the mouse.

### The Everyday Analogy
**Typing versus hunt-and-peck.** Nobody sets out to be slow with the mouse, but every trip to a menu adds up over thousands of actions a day.

### Why it matters
- Small time savings **compound** across a whole career.
- Staying on the keyboard keeps you **in flow**.
- Some shortcuts differ by operating system, so know yours.

### Shortcuts Inherited from the Operating System

These work in VS Code exactly as they do elsewhere: **Save**, **Copy**, **Paste** (`Ctrl` on Windows/Linux, `Cmd` on macOS).

### Application-Specific Shortcuts

- **Format file:** runs your configured formatter (such as **Prettier** in a JavaScript project) on the open file.
- **Search all files:** searches the text of every file in your workspace.
- **Find and replace across files:** project-wide replace.
- **Delete line:** removes the current line.
- **Hide sidebar:** frees up room for code.
- **Zoom in/out:** scales the whole editor.
- **Command Palette:** your safety net. Forget a shortcut? Open this and **search for the action by name**.

### Multi-Line (Multi-Cursor) Editing

- **What it is:** Place several cursors at once so anything you type or delete applies to **all of them simultaneously**.
- **Analogy:** Editing with **several pairs of hands**. One typing action, many places changed.
- **Why it matters:** Perfect for repetitive edits, like adding quotes around a column of words or renaming similar variables.
- **How:** Use the add-cursor shortcut to extend to consecutive lines, or hold `Alt` (`Option` on macOS) and **click** wherever you want a cursor.

### Quick Reference Table

| Action | Windows | Linux | macOS |
|---|---|---|---|
| Save | `Ctrl + S` | `Ctrl + S` | `Cmd + S` |
| Copy | `Ctrl + C` | `Ctrl + C` | `Cmd + C` |
| Paste | `Ctrl + V` | `Ctrl + V` | `Cmd + V` |
| Format file | `Shift + Alt + F` | `Ctrl + Shift + I` | `Shift + Option + F` |
| Search all files | `Ctrl + Shift + F` | `Ctrl + Shift + F` | `Cmd + Shift + F` |
| Find and replace (all files) | `Ctrl + Shift + H` | `Ctrl + Shift + H` | `Cmd + Shift + H` |
| Delete line | `Ctrl + Shift + K` | `Ctrl + Shift + K` | `Cmd + Shift + K` |
| Hide sidebar | `Ctrl + B` | `Ctrl + B` | `Cmd + B` |
| Zoom in | `Ctrl + Plus` | `Ctrl + Plus` | `Cmd + Plus` |
| Zoom out | `Ctrl + Minus` | `Ctrl + Minus` | `Cmd + Minus` |
| Add cursor above/below | `Ctrl + Alt + Up/Down` | `Shift + Alt + Up/Down` | `Option + Cmd + Up/Down` |
| Add cursor on click | `Alt + Click` | `Alt + Click` | `Option + Click` |
| **Command Palette** | `Ctrl + Shift + P` | `Ctrl + Shift + P` | `Cmd + Shift + P` |

### Bonus Shortcuts Worth Learning

These are not in the original lesson, but they are used daily by most VS Code developers (`Cmd` replaces `Ctrl` on macOS):

| Action | Shortcut |
|---|---|
| Quick-open a file by name | `Ctrl + P` |
| Toggle line comment | `Ctrl + /` |
| Select the next matching word (multi-cursor) | `Ctrl + D` |
| Move the current line up/down | `Alt + Up/Down` |
| Duplicate the line | `Shift + Alt + Up/Down` (Windows) |
| Open/close the integrated terminal | `` Ctrl + ` `` |

### Make Formatting Automatic

```json
// .vscode/settings.json (applies to this workspace only)
{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode"
}
```

> **Dev Tip:** You do not need to memorize everything. Learn **`Ctrl + Shift + P`** first, and add **one new shortcut per week** until they stick.

## 5. Extensions

### What they are
Add-ons from the VS Code marketplace that add features: themes, linters, formatters, AI helpers, and more.

### The Everyday Analogy
**Apps on your phone.** The phone (VS Code) works out of the box, but apps (extensions) make it *yours*.

### Why they matter
- Turn a lightweight editor into a tailored dev environment.
- Catch errors and style problems **while you type**.
- Make code easier to read and navigate.

### Quick Example: Install from the Terminal

```bash
code --install-extension esbenp.prettier-vscode
code --install-extension dbaeumer.vscode-eslint
code --install-extension usernamehw.errorlens
```

### Productivity and Readability

| Extension | What it does |
|---|---|
| **Better Comments** | Highlights special comments: TODOs, questions, and warnings stand out. |
| **Code Spell Checker** | Flags misspelled words. Built for code, so it understands camelCase. |
| **Error Lens** | Highlights the **whole line** and shows the error message inline, instead of just a small underline. |
| **Indent Rainbow** | Colors each indentation level. Combined with VS Code's built-in bracket pair colorization, it makes scope easy to see. |
| **Colorize** | Shows the actual color for CSS values like `#ff5733`. |
| **VS Code Great Icons** | An icon pack for a cleaner, scannable file tree. |

### AI Assistants

- **GitHub Copilot** and **Tabnine** give **inline suggestions** as you write.
- **Analogy:** An autocomplete that finishes whole sentences.
- **Pitfall:** Treat suggestions as a **first draft**. Read and test everything it writes before you commit it.

### Language-Specific Extensions

| Language | Extensions | Purpose |
|---|---|---|
| **JavaScript** | **ESLint** and **Prettier** | Linting (catch bugs and bad patterns) and formatting (consistent style) |
| **TypeScript** | **Pretty TypeScript Errors** | Turns cryptic TS errors into readable messages |

### Just for Fun

- **VS Code Pets:** configurable virtual pets that keep you company while you debug.
- **Power Mode:** flashy effects when you hit a high "combo" of typing.
- **Discord Presence:** shows your friends what you are working on.

> **Production Pitfall:** Too many extensions slow down startup and increase your attack surface, so install only what you use, check the **publisher and install count** before adding one, and disable or remove the ones you do not need.

## Final Tips

- **Start simple:** VS Code, Live Server, Prettier, and ESLint cover a lot of ground.
- **Learn one shortcut at a time:** add a new one each week.
- **Keep your extension list lean:** every extra one costs startup time.
- **Practice:** Create a `my-project` folder from the terminal, open it with `code .`, build a small `index.html`, and run it with Live Server, all without touching the mouse where possible.
